# ADR 0003: 候选＝知识注入通道；名字校准合一（term/naming），表述理顺归润色

日期：2026-09-16｜状态：已实施

## 决策

候选系统只做一件事：**把你说话里说不清的点，校准成对的名字**。

- 一份任务书「名字校准」（替代原「候选生成」）：找出说话里**说不清的点**（一个东西、东西的某个部分、几样东西之间的关联——什么都有可能），**先认后造**——业界已有本名的，给本名＋白话注释（认得出）；要新造的，按领域惯例起名＋理由（立得住），尽量沿用本名作词根；一个点只出一个名字，优先挑最影响理解的点（总量上限照旧）。
- 输出契约 kind 从 `term|phrase|naming` 改为 `term|naming`；phrase（顺句）从候选移除，归润色职责（形式自动处理，无需用户选）。
- 分界原则：**润色管形式（自动、每段、无需选），候选管知识注入（用户没说、但这句话需要的东西，必须用户点头）**。

## 为什么

1. phrase 与指令化润色重叠：顺句是形式问题，润色流已在做；候选里再放一份＝重复＋噪音。
2. term 与 naming 同产物（名字）同链条（认出行话→用行话给新造物起名）；拆两份任务书会对同一个点给出互不相干的双份名字，「先认后造」的决策规则必须写在一份正文里才连贯。
3. term chip 必须配白话注释（识别优于回忆，NN/g #6）：用户说不出术语是回忆失败，看到「术语＋就是你说的那个X」能认出来——注释同时拦截 AI 认错所指（"讲成另外的东西"在贴出前被发现）。
4. naming 要配理由：命名是 Agent 时代的性能特征，坏名字固化进实现、事后改名触及每一处调用点（Symvanta《Should You Rename Your Code for AI Agents》；微软 HAX Toolkit Pattern 10A「行动前消歧」：给选项优于追问、最可能的排前）。

## 替代对照

- 拆三份任务书（术语补全/表述理顺/命名校准）：否——phrase 与润色重叠；term/naming 链条被拆断。
- 只重写「候选生成」一份正文不拆不并：否——三判据挤一份正文成大杂烩，调优互相牵制（本方案即其修正态）。
- 反问澄清（AI 提问）：否——打断说话流；任务型语音对话研究显示给选项优于多回合追问。

## 失效条件与盲区

- 若「卡在半句不知道下半句怎么讲」成为高频痛点，那是**续写**功能（另立），不是恢复 phrase。
- 多点场景的归属呈现靠注释回指（「就是你说的那个X」）；若未来证明不够，再考虑按所指分组展示（未做）。
- 白话注释在浮框上的展示形态（hover/小字）实施时定。
